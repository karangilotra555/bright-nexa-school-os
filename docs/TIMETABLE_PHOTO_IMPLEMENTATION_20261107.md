# Bright Nexa: School Timetable & Student Photos — Implementation and Release

Status: **review branch only**, PR #66 depends on shared Student & Parent Portal PR #64. Supabase remains primary. No live school records or Storage files were changed.

## Research basis

Professional timetable builders use a consistent workflow:
1. Create Classes/Sections and subject/teacher mappings, including weekly lesson load.
2. Configure school working days, period boundaries, lunch/assembly and teacher availability.
3. Fill a Monday–Saturday class grid (manual) or generate schedules from constraints.
4. Validate duplicate teacher/room bookings, breaks and unassigned teachers.
5. Review and publish the approved class timetable; student and parent view should not show drafts.
6. Print/Export class timetable and view each teacher's allocated lessons.

Examples researched:
- School Orbit Timetable Documentation: https://www.schoolorbit.in/docs/academics/timetable
- SchoolTimetable.in: https://www.schooltimetable.in/help
- aSc TimeTables: https://help.asctimetables.com/index.php?id=947&lang_id=1
- School Timetable for India: https://www.timetableforme.in/help/

## Current Bright Nexa UI (admin)

Open **Teacher & Staff Portal → School OS ERP (Admin) → Class & Teacher Timetable**.

The new page `/school-timetable.html` uses the same navy/blue styles as the approved school portal and does not replace the existing React ERP UI.

- **Authorized school:** Supabase verified logged-in School Admin only. Multi-school selector lists active school memberships; it does not grant additional school access.
- **Period setup:** Choose Mon–Fri or Mon–Sat, start time, length, period count, and lunch break. These are editable *suggested defaults*, not school records. Saving creates the actual school's period structure; existing structures cannot be reset by the wizard.
- **Class/Section selector:** Only live `school_classes` rows.
- **Class grid:** Mon–Sat columns, periods/timings rows. Click a lesson to enter subject, allowed assigned teacher, optional room. Use existing Staff Roles & Permissions to add/revoke teacher/class and subject mappings.
- **Teacher view:** Show selected teacher's booked classes.
- **Clash protection:** unique teacher/room/time slot, one lesson per class/period, no overlaps within the school period structure, no lesson in break period, and verify teacher is currently allocated to that class/subject.
- **Publish:** Draft changes are private. Publishing requires at least one lesson and all existing lesson rows to have teachers. Any edit to a lesson or period, or removal/change of teacher allocation, unpublishes the affected class. Re-review required before re-publishing.
- **Print/Save PDF:** Browser Print button renders the grid in print style. The PDF is generated by the browser; no server-side export is claimed.

**Not yet in this version:** full automatic timetable optimization, special half-day class schedules, teacher availability constraints, substitute teacher workflow and subject weekly target quotas. These are advanced release items. Do not claim the manual editor is a fully optimized automatic generator.

## Parent/student timetable

`bn_portal_class_timetable(institution_id,student_id)` is a read-only RLS-safe RPC that checks a *specific linked child* and only returns published periods and their assigned subject, room, teacher display name and times. The existing Student & Parent Portal shows a mobile-scrollable six-day grid. A class timetable without publication remains private.

`bn_portal_class_teachers` from PR #64 shows class teacher + subject-wise teacher mapping from the same role assignments. No teacher private contact details are returned.

## Private photo workflow

Admin: **Teacher & Staff Portal → Student Profiles → Search student → Load profile → Choose photo → Save student details & photo**.

- JPEG, PNG or WebP up to 5 MB. Unique image path `<school>/<student>/<file-id>.<extension>`.
- Bucket `school-student-photos` is private; no public URL, anonymous upload, or cross-school/child access.
- Supabase Storage policies permit upload to a verified School Admin for an *active existing student*. Parent/Student can read only a linked child.
- A separate `bn_student_photo_save` RPC verifies the school admin, immutable child ID, tenant and uploaded object before changing only `school_student_profiles.details.student_photo_path`.
- Existing APAAR ID, contact, health and other profile details stay untouched by the photo RPC.
- Parent web/mobile obtains a 5-minute signed URL after authenticated profile read; the photo appears in the overview avatar and student detail profile. Missing photo shows initials rather than a fake image.
- Old image files are deliberately not automatically deleted by replacing photos; cleanup must be tenant-scoped and separate.
